it asked for. Rust backend, one FreeBSD box, two jails behind Caddy.

On the side, [**trongate.cloud**](https://trongate.cloud): hosting for
[Trongate](https://trongate.io) apps on Kubernetes. You push, we deploy, and an
MCP server lets an assistant do the same. Still a work in progress.

To dogfood it, [**Recruiter**](https://recruiter.trongate.dev): a Trongate app
running on trongate.cloud. Its core is `cv_match`: paste or upload a job post,
and it matches your CV against each requirement, first through a Danish/English
skills taxonomy and then a language model for what the taxonomy can't decide,
and drafts the application and a tailored résumé from the result.

<summary><sub>Developing the site</sub></summary>

With [mise](https://mise.jdx.dev), `mise install` sets up Rust, Node and
watchexec, and these tasks cover the day to day:

```sh
mise run serve   # build, then serve ./public at http://localhost:8000
mise run dev     # the same, rebuilding and restarting on every change
mise run check   # everything CI checks
```

Without mise, the same thing in plain cargo:

```sh
cargo run --release                  # build into ./public
cargo run --release -- serve [port]  # build, then serve it (default port 8000)
```

`serve` is a small built-in server (`src/serve.rs`) that resolves URLs the way
the live Caddy config does, `/blog` → `/blog/` redirect included.

Checks, as CI runs them:

```sh
cargo fmt --check
cargo clippy -- -D warnings
cargo test
node --test js/retrieval.test.mjs   # after a build; Node 22+, nothing to install
```

Posts live in `content/blog/`, the CV in `content/cv.toml`, and the AI
article's knowledge nodes in `content/ai/` — see
[docs/knowledge-nodes.md](docs/knowledge-nodes.md).
