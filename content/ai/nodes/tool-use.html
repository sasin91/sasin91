When an application describes some tools in the prompt, such as a name, a purpose and the arguments each takes, a model trained for it can respond with a structured call instead of prose: in effect, “call search with these arguments”.

The model executes nothing. The application around it parses the request, decides whether it is allowed, runs it, and appends the result to the context as more tokens. Then generation continues, now with the result in view. Permissions, sandboxing and logging all live in that application, never in the model.

An agent is this loop repeated: generate, call a tool, read the result, generate again, until the task is done. Retrieval is often just one of the tools, alongside running code, reading files or calling an API.

How tools are described to the model and connected to the application varies between vendors. MCP is one attempt to standardise the connection side.
