# Rebuilding sasin91.xyz as a static site

**Date:** 2026-07-27
**Status:** approved design, ready for an implementation plan

## Why

Training moved to athletos.app. What remains at sasin91.xyz is a CV page and
four blog posts, currently served by a full Laravel 13 + Inertia + React
application: Fortify auth, two-factor, Octane, Nightwatch, spatie/health,
SQLite, and roughly 16,600 lines of TypeScript. Each blog post is a hand-written
React component with its own controller method and hardcoded route.

That is an authenticated web application serving five pages of prose. The
rebuild replaces it with a static site generated by a small Rust binary.

## What was evaluated

Four prototypes were built to decide this, each rendering the same three pages
from the same prose with the same stylesheet, so the toolkit was the only
variable. They live on the `prototype/ssg-bakeoff` branch under `prototypes/`,
with measurements in `prototypes/COMPARISON.md`.

| | Astro | Zola | Jigsaw | Rust + Djot |
|---|---|---|---|---|
| Build | 6.39s | 0.48s | 1.73s | **0.11s** |
| Deps on disk | 145 MB | 0 | 28 MB | 0 at runtime |
| Source maintained | 249 ln | 135 ln | 196 ln | 624 ln |
| Template typo | silent blank | silent blank | silent blank | **compile error** |

Jigsaw was eliminated: its default parser is Michelf MarkdownExtra rather than
CommonMark, so fenced code with an info string silently rendered as inline
`<code>`; Blade does not run in `.md` files; the config key `site` is reserved
and yields a null; there is no syntax highlighting by default and the obvious
package is abandoned. Every failure was silent.

Zola was the runner-up and remains the fallback if the Rust builder ever
becomes a burden. It was rejected only because the compile-time guarantees and
control were wanted more than the 490 lines it would have saved.

## Decisions

### Generator: a Rust binary in this repo

Roughly 620 lines. It walks `content/`, renders through Askama templates, and
writes `public/`. Output is disposable and fully regenerated on every run —
nothing is mutated in place, so the site is reproducible from source alone.

Dependencies: `jotdown`, `latex2mathml`, `syntect`, `askama`, `serde`, `toml`,
`chrono`, `walkdir`, `anyhow`. All compile-time only; the artifact is a single
binary with no runtime dependencies.

### Authoring format: Djot

Djot (John MacFarlane, who also wrote CommonMark) is used instead of Markdown
because the three things these posts need are native syntax rather than
extensions:

- `::: warning` … `:::` — a div with a class, for callouts
- `{title="4-remaster.sh"}` — attributes on any block, for code filenames
- ``$`…` `` and ``$$`…` `` — inline and display math

It also has a raw-HTML block (`` ``` =html ``), so a post can drop into plain
HTML styled by CSS at any point. "Post is code" stays available inside a prose
file.

**Known cost:** Djot inverts Markdown's emphasis — `*x*` is strong, `_x_` is
emphasis. `prototypes/_shared/to-djot.mjs` converts the existing posts and has
been run successfully against the FreeBSD post.

**Known risk:** `jotdown` has one maintainer and ~99k downloads a quarter,
thinner than Zola, which was itself criticised on bus factor during evaluation.
This is accepted because the coupling is small — the parser is touched in about
86 lines — the format is specified independently by jgm with other
implementations in JS and Lua, and the posts are plain text regardless.

### Templates: Askama

Jinja/Twig syntax, compiled and type-checked against the structs they render.
`{{ post.titel }}` is `error[E0609]: no field 'titel'`, not a blank space on a
published page. This was the deciding property over Zola's runtime Tera.

### Syntax highlighting: syntect, emitted as CSS classes

Solarized (light) in light mode, base16-ocean.dark in dark, written once to
`public/syntax.css` (~12 KB) behind a `prefers-color-scheme` query. Classes
rather than inline styles, so both palettes live in one file instead of being
repeated on every token, and changing theme is a CSS edit.

### Math: MathML at build time

`latex2mathml` renders formulas during the build. Browsers display MathML
natively, so the site ships **zero JavaScript** — no KaTeX, no MathJax, no
webfonts. A formula that fails to parse renders visibly as
`<code class="math-error">` with the parser message in a `title` attribute,
rather than disappearing.

### Design

Single column, ~68ch measure, system sans stack, restrained palette with one
accent, light and dark via `prefers-color-scheme`. No gradients, beams, or
animated backgrounds. The stylesheet is plain CSS — roughly 300 lines, no
Tailwind — styling semantic HTML elements directly, with a small number of
classes (`.callout`, `.codeblock`, `.prose`, `.timeline`).

### Site structure

| URL | Content |
|---|---|
| `/` | Name, one or two sentences, links, then recent posts |
| `/about` | Career timeline, from `content/cv.toml` |
| `/blog/` | All posts, reverse chronological |
| `/blog/<path>/` | A post |
| `/rss.xml`, `/sitemap.xml`, `/robots.txt` | Generated |

Existing post URLs are preserved exactly:

```
/blog/trongate
/blog/trongate/mx-transition      <- nested one level deeper
/blog/freebsd-on-hetzner
/blog/athletos-freebsd
```

Two consequences the prototype does not yet handle:

1. **Paths are not flat.** `mx-transition` lives under `trongate/`. A post's
   output path therefore comes from an explicit `path` key in its frontmatter,
   not from the filename. The prototype derives the slug from the file stem and
   would flatten this URL, breaking an existing link.
2. **No trailing slashes today.** The current routes serve `/blog/trongate`
   with no trailing slash. Writing `<path>/index.html` means Caddy must resolve
   the extensionless request; `try_files {path} {path}/ {path}/index.html` in
   the site block covers it without a redirect. This must be verified against
   the real URLs after deploy, not assumed.

Writing is the front door; the career history moves off the homepage to
`/about`.

### Deployment

CI builds the binary and the site, then rsyncs `public/` over SSH to the
FreeBSD box that already runs athletos.app. Caddy gets a second site block
alongside the existing one and handles certificates itself, as it already does.
One machine, no new hosting accounts.

## Repository layout

```
content/
  cv.toml              profile and timeline
  blog/*.dj            one file per post, +++ TOML frontmatter +++
src/
  main.rs              frontmatter, loading, templates, build
  djot.rs              code blocks and math, off the event stream
  highlight.rs         syntect, class-based, dual theme
templates/
  base.html index.html about.html blog.html post.html
  rss.xml sitemap.xml
static/
  site.css  images/
```

## Scope

**In:** the generator, the five page types, the four existing posts converted
to Djot, the stylesheet, RSS/sitemap/robots, CI build and deploy, a local
watch loop (`watchexec -e dj,html,css -- cargo run`).

**Out:** search, tags/taxonomies, pagination, comments, analytics, a dev server
with live reload beyond the watch loop, and any JavaScript. Pagination and tags
are deliberately deferred until there are enough posts to need them.

**Deleted:** the entire Laravel application — `app/`, `bootstrap/`, `config/`,
`database/`, `routes/`, `resources/js/`, `vendor/`, `node_modules/`,
`composer.json`, `package.json`, and the training feature. Git history retains
all of it.

## Verification

- `cargo build` must succeed — this is what checks the templates.
- Every pre-existing URL must resolve. The list is fixed and taken from the
  current `routes/web.php`: `/blog`, `/blog/trongate`,
  `/blog/trongate/mx-transition`, `/blog/freebsd-on-hetzner`,
  `/blog/athletos-freebsd`, and `/`. Check them against the deployed site, not
  just the local `public/` tree, since trailing-slash behaviour is Caddy's.
- Rendered output for each converted post is diffed against the current site's
  prose to confirm the Djot conversion lost nothing.
- `public/` contains zero `<script>` tags.
- RSS and sitemap validate.
